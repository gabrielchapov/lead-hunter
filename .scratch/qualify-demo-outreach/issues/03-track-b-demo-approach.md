## Question

For established/automation-track leads (Track B), does the demo need a discovery call first (like Caliper), or can a first-pass prototype be built from observable info alone, the same way Track A works from public data?

## Answer

No pre-built artifact for Track B's initial outreach — this breaks symmetry with Track A on purpose. A website demo only needs public info (name, category, address); an automation prototype needs to know what's actually in the lead's spreadsheet or how their process really works, which isn't observable from outside. Caliper doesn't skip their discovery call either — they can't.

Track B's outreach leads with a case-study-style pitch using a real (if borrowed/generic at first) proof point — e.g. "we cut [similar business]'s data entry by 80%, want a free 30-min call to see if we can do the same for you?" — not a bespoke pre-built artifact. The actual scoped prototype only gets built after a real conversation, mirroring Caliper's discovery-call → prototype-demo → build → iterate flow (see map Notes for the reference link).

"Demo-first" for Track B is satisfied by proof-of-competence (a real case study), not a bespoke artifact per lead.
